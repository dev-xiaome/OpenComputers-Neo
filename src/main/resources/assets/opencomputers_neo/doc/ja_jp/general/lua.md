# Lua 

Lua の[リファレンスマニュアル](http://www.lua.org/manual/5.2/manual.html)と [Programming in Lua](http://www.lua.org/pil/)（初版はオンラインで無料公開されています）の書籍は、Lua の基本を学び、標準ライブラリや構文に慣れるための良い出発点です。 [OpenOS](openos.md) は標準ライブラリを非常に忠実にエミュレートするよう努めていますが、サンドボックス化の理由から、デバッグライブラリがほとんど欠如しているなどの例外もあります。これらの違いは[Wikiでドキュメント化されています](https://ocdoc.cil.li/api:non-standard-lua-libs)。

非標準ライブラリをスクリプトで使用するには、`require` でインポートする必要があります。例：

`local component = require("component")`
`local rs = component.redstone`

これにより、[レッドストーン](../item/redstoneCard1.md)コンポーネントが提供するすべての関数を呼び出せるようになります。例：

`rs.setOutput(require("sides").front, 15)`

**重要**: Lua インタープリターで作業する場合は、`local` を使用 *しないでください*。`local` を使用すると、その変数は単一の入力行に対してのみ有効になります。つまり、上の行をインタープリターで1つずつ入力した場合、3行目で `rs` が `nil` であるというエラーが発生します。なぜ3行目だけなのか？ それは、テストを容易にするために、インタープリターは不明な変数をライブラリとしてロードしようとするからです。そのため、1行目の `component` への代入は何もしませんが、2行目で `component` を使用すると、そのライブラリがロードされ、使用されます。ライブラリは、メモリ使用量を低く抑えるために、Lua スクリプトの使用時には自動的に使用されません。

OpenOS は、[コンピューター](computer.md)に接続されたコンポーネントの制御や操作から、バンドルされたレッドストーン制御に使用される色のリファレンス API、[キーボード](../block/keyboard.md)のキーコードまで、多くのカスタムライブラリを提供しています。カスタムライブラリは、上記のように `require()` 関数を使用することで Lua スクリプト内で使用できます。一部のカスタムライブラリは特定のコンポーネントを必要とします（例：`internet` ライブラリには [インターネットカード](../item/internetCard.md) が必要です）。この特定のケースでは、インターネットカードをインストールするとライブラリが表示されるようになります。技術的には、インターネットカード上の小さな読み取り専用ファイルシステムに含まれています。
